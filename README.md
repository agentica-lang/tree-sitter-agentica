# tree-sitter-agentica

A [tree-sitter](https://tree-sitter.github.io) grammar for Agentica, a language
best described as "Ruby with types".

It is used for:

- syntax highlighting in editors;
- structural search and rewrite with ast-grep.

This grammar is a work in progress.

## Layout

- `grammar.js`: the grammar.
- `src/scanner.c`: the external scanner (see below).
- `src/parser.c`, `src/grammar.json`, `src/node-types.json`: generated by
  `tree-sitter generate`; they are committed.
- `queries/`: `highlights.scm`, `tags.scm` and `locals.scm`.
- `test/corpus/`: corpus tests, one file per area.
- `script/parse-agentica-repo.sh`: parses every Agentica source of the
  interpreter repository.
- `ast-grep/`: an ast-grep project with the `agentica` custom language and
  example rules.

## Build and test

Every command runs from the repository root. `tree-sitter-cli` is a pinned
dev dependency, so nothing is installed globally.

```sh
npm ci                                  # install the pinned tree-sitter-cli
npx tree-sitter generate                # rebuild src/parser.c from grammar.js
npx tree-sitter test                    # corpus tests in test/corpus/
npx tree-sitter build -o agentica.so    # shared library for ast-grep
npx tree-sitter parse file.agc          # print the tree of one file
```

`script/parse-agentica-repo.sh [path]` parses every `.agc` file in
`examples/`, `stdlib/`, `tests/fixtures/` and `tests/bdd/` of the interpreter
repository (default `~/apps/agentica`, or `$AGENTICA_REPO`) and every
`agentica` code block in `site/content/`. It fails when a file has an `ERROR`
or `MISSING` node. Fixtures that are invalid on purpose are skipped: the
allowlist is every fixture whose `.expected` result has a `LEX-` or `PARSE-`
`"code"`, computed on each run.

## Node types

Declarations: `function_definition` (`name`, `parameters`, `return_type`,
`body`), `parameter`, `struct_definition` (`name`, `field`),
`field_declaration`, `enum_definition` (`name`, `type_parameters`, `variant`),
`enum_variant` (`name`, `payload`), `import` (`path`, `alias`) and `export`
(`declaration`).

Statements: `assignment` (`left`, `type`, `right`), `compound_assignment`
(`left`, `operator`, `right`), `return`, `break`, `next`, `if` (`condition`,
`consequence`, `alternative`), `elsif`, `else`, `while` (`condition`, `body`),
`for` (`variable`, `iterable`, `body`), `case` (`value`, `arm`) and `case_arm`
(`pattern`, `body`). Agentica has no `when`: an arm is `pattern -> body`.
Patterns are `variant_pattern` (`variant`, `bindings`), `negative_number`,
literals and identifiers (`_`).

Expressions: `binary` (`left`, `operator`, `right`), `unary`, `range`
(`begin`, `operator`, `end`), `try`, `call` (`module`, `function`,
`arguments`, `block`), `method_call` (`receiver`, `method`, `arguments`,
`block`), `field_access` (`receiver`, `field`), `index`, `function_reference`,
`construct` (`type`, `arguments`), `named_argument`, `type_path`
(`Color.Red`), `block` (`parameters`, `body`) with `block_parameter`, `list`,
`map` with `pair`, `string` with `string_content`, `escape_sequence` and
`interpolation`, `integer`, `float`, `true`, `false` and `nil`.

Types: `type` (`name`, `arguments`), `scoped_type_identifier`
(`Models.User`), `type_arguments` and `type_identifier`.

`IO.puts(x)` is a `call` with a `module`; `xs.size` without parentheses is a
`field_access`, as in the interpreter's parser.

## The scanner

The external scanner in `src/scanner.c` handles what a context-free lexer
cannot:

- Newlines. A newline ends a statement, but inside `(...)`, `[...]` and
  `{...}` it is ignored, except inside a `do ... end` block written there. The
  scanner emits a newline token only where the parser accepts one; elsewhere
  the newline is whitespace.
- `name!=`. A trailing `!` belongs to a name, but not when `=` follows, so
  `a!=b` is `a != b`.
- `break` and `next` are loop control only when they stand alone on a line;
  otherwise they are ordinary names (`next = 1`).
- `do` after a `while`, `for` or `case` header belongs to the loop, not to a
  block on the last call: `while xs.any? do`.
- String text, which may hold any character (even NUL) except `"`, `\`, a
  newline and `#{`.

## Differences from the interpreter

The grammar accepts a little more than the interpreter does, to stay simple
and to suit tools:

- Statements are allowed at the top level, so ast-grep patterns such as
  `$X = $X.push($Y)` parse on their own.
- The blank line required between declarations is not checked.
- Comparisons, equalities and ranges may chain.
- An expression may continue on the next line after a binary operator.
- Any name is accepted as a `case` pattern, and positional and named
  arguments may mix.

## ast-grep

Build the library, then run ast-grep from the `ast-grep/` directory, which
holds `sgconfig.yml`:

```sh
npx tree-sitter build -o agentica.so
cd ast-grep
ast-grep run --lang agentica -p '$X = $X.push($Y)' ~/apps/agentica/stdlib
ast-grep scan ~/apps/agentica/stdlib    # run every rule in rules/
ast-grep test --skip-snapshot-tests     # check the rules against rule-tests/
```

`sgconfig.yml` registers the `agentica` language for `.agc` files and uses
`µ` as the expando character, since `$` is not valid in Agentica names.

`rules/quadratic-append.yml` warns on `xs = xs.push(y)`, and on `s += t` when
`s` is a String (it is assigned a string literal, or declared `String`),
inside a `while` or `for` loop. Each pass copies the whole value, so the loop
is quadratic.
